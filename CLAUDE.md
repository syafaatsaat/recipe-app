# Recipe App

## Read first
**`docs/design.md` is the binding design doc** (stack, schema, scaling rules, build order). Read it before any work.
- Follow its decisions. If something in it looks wrong or is missing, propose a change to the doc and get agreement. Don't quietly deviate or invent a new approach.
- When a decision changes, update the doc in the same change, so the next session reads the current state.

## Non-negotiable rules
- **Never persist scaled quantities.** Stored recipes are always the base. Scaling is a pure `render(baseRecipe, scaleState, units)` call.
- `lib/culinary/` is pure TS: no I/O, no React, no DB imports.
- **Migrations:** `supabase/migrations/*.sql` (raw SQL) is the source of truth for the schema, RLS and triggers. Drizzle is only for typed queries, and `db/schema.ts` is generated by `drizzle-kit pull`. Never hand-edit it, and never use `drizzle-kit push/generate`.
- Drizzle connects as `postgres`, which **bypasses RLS**. User-scoped queries must go through `db/withUser.ts`.
- Pin exact dependency versions (no `^`/`~`).

## Commands
- `pnpm test`: Vitest
- `npx supabase start`, then `npx supabase db reset` to apply the migrations and seed
- `npx supabase test db`: pgTAP schema/RLS tests in `supabase/tests/`
