## Non-negotiable rules
- **Never persist scaled quantities.** Stored recipes are always the base. Scaling is a pure `render(baseRecipe, scaleState, units)` call.
- `lib/culinary/` is pure TS: no I/O, no React, no DB imports. Its tests are the spec: change a display rule in doc §5 first, then its test, then the code.
- **Migrations:** `supabase/migrations/*.sql` (raw SQL) is the source of truth for the schema, RLS and triggers. Drizzle is only for typed queries, and `db/schema.ts` is generated by `pnpm db:pull` (a patched `drizzle-kit pull`). Never hand-edit it, and never use `drizzle-kit push/generate`. `db/relations.ts` is hand-written, so update it when FKs change.
- Schema change = new migration file + pgTAP test + `pnpm db:pull`. Don't edit migrations that have been applied to a hosted project.
- Drizzle connects as `postgres`, which **bypasses RLS**. User-scoped queries must go through `db/withUser.ts`.
- **Identity comes only from `lib/auth.ts`** (`getUser()`/`requireUserId()`). Never trust a user id from the client, and never use `getSession()` on the server. `proxy.ts` redirects are a convenience, not a guard.
- With Cache Components on, anything that reads cookies, params or searchParams goes inside `<Suspense>`.
- Next 16 keeps recently visited pages mounted but hidden. Never hard-code element ids (`id="email"`): use `useId()`. In e2e tests, field lookups use `.filter({ visible: true })`.
- Scale and units live only in the URL (doc §3.5). `components/recipes/view/recipe-view.tsx` reads them with `useSearchParams` and writes them with `history.replaceState`. Don't add a server round-trip or a history entry per tap.
- Pin exact dependency versions (no `^`/`~`; `saveExact` is set). Don't bypass pnpm's `minimumReleaseAge` quarantine. Pick an older release instead.
- `AGENTS.md` comes from Next.js: Next 16 may differ from training data, so check `node_modules/next/dist/docs/` before using Next APIs.

## Run locally
1. `npx supabase start`, then `pnpm db:reset` (migrations + seed). A reset deletes every account: sign up again afterwards (an old session is signed out on its first save).
2. `cp .env.example .env.local` (local default keys, not secrets)
3. `pnpm dev`, open http://localhost:3000, create an account. Emails (password reset) land in Mailpit at http://127.0.0.1:54324

## Commands
- `pnpm test`: Vitest unit tests (`lib/**`, no DB)
- `pnpm test:db`: Vitest integration tests (`db/**`, needs local Supabase)
- `npx supabase start`, then `pnpm db:reset` to apply the migrations and seed
- `pnpm db:test`: pgTAP schema/RLS tests in `supabase/tests/`
- `pnpm db:pull`: regenerate `db/schema.ts` after a migration
- `pnpm test:e2e`: Playwright flows against `pnpm dev` + local Supabase (first time: `npx playwright install chromium`). It also starts `e2e/fixture-server.mjs` (recipe pages on 127.0.0.1:4010). The same server mocks the Claude API. If you start `pnpm dev` yourself, start it as `IMPORT_ALLOW_HOSTS=127.0.0.1:4010 ANTHROPIC_BASE_URL=http://127.0.0.1:4010 ANTHROPIC_API_KEY=e2e-mock pnpm dev`, or the import flows can't fetch the pages and the AI flows would call the real API (with a real key in `.env.local`) or none.
- `pnpm lint`, `pnpm build`
